## 2. Findings

Each finding: route · repro · expected vs actual · location.

### High

**F-01 — A cancelled meeting permanently blocks its slot** (functional)
- *Route:* `/admin/meetings` → cancel, then `/api/meetings/book`.
- *Repro:* book 2026-11-12T09:00Z → cancel it in admin (dialog says *"This frees the … slot"*) → slot reappears in `/api/meetings/availability` → book it again.
- *Expected:* 201. *Actual:* `409 "That slot was just taken"` every time, forever.
- *Cause:* `Meeting.scheduledAt` is globally `@unique` (`prisma/schema.prisma:144`) while availability only excludes `CONFIRMED` rows (`src/app/api/meetings/availability/route.ts:20-23`). The cancelled row still owns the unique key.
- *Fix direction:* partial unique index `UNIQUE (scheduledAt) WHERE status = 'CONFIRMED'` (raw SQL migration; Prisma can't express it) and drop `@unique`.

**F-02 — No login rate limiting or lockout**
- *Route:* `POST /api/auth/callback/credentials` (and the `/admin/login` Server Action).
- *Repro:* 30 wrong passwords for a real admin in **2 s**; all processed; the correct password still works immediately after.
- *Expected:* throttling per IP and per account. *Actual:* none.
- *Location:* `src/auth.ts:15-31`.

**F-03 — Sessions cannot be revoked; a deleted admin keeps full access**
- *Repro:* create admin → log in → `DELETE` the `AdminUser` row → same cookie still loads `/admin/leads` (200, lead data visible) and still uploads files.
- *Expected:* access ends when the account is removed/suspended. *Actual:* lasts until JWT expiry (Auth.js default 30 days; no `maxAge` set).
- *Cause:* JWT strategy with no DB check — `src/auth.ts:11,35-42`, `src/lib/admin-guard.ts:9`, `src/app/admin/(protected)/layout.tsx:15`.

**F-04 — Public endpoints are unthrottled and send mail to any address**
- *Routes:* `POST /api/leads`, `POST /api/meetings/book`.
- *Repro:* 25 leads in < 1 s, all 201, 50 emails sent. Each lead sends a "Thanks for reaching out" mail to the submitted address, with the attacker-chosen `name` in the body; each booking sends an `.ics` to the submitted address.
- *Impact:* the site can be used to mail arbitrary third parties, damaging the sending domain's reputation, and to flood the DB/inbox.
- *Location:* `src/app/api/leads/route.ts:16-70`, `src/app/api/meetings/book/route.ts:17-118`.

### Medium

**F-05 — Admin validation errors crash the page instead of showing a message**
- *Repro:* `/admin/availability` → Add rule → start 17:00, end 09:00 → submit.
- *Expected:* "Start time must be before end time" under the field. *Actual:* full-screen "Something went wrong — usually a temporary database or network issue". Server log shows the correct `ZodError`.
- *Cause:* every action uses `schema.parse()` and throws (e.g. `availability/actions.ts:21-27`); no dialog catches it (e.g. `services/service-form-dialog.tsx:46-49`). Applies to all 9 modules.

**F-06 — Booking failures are silent on the public site**
- *Repro:* in the browser, pick the slot from F-01 → fill the form → "Book".
- *Expected:* an error message. *Actual:* form resets, no message.
- *Cause:* `handleBook` sets the error then calls `loadSlots()`, which immediately does `setError(null)` — `src/components/public/scheduler.tsx:97-98` vs `:27`.

**F-07 — Booking window not enforced server-side**
- *Repro:* `POST /api/meetings/book` with `2027-12-06T10:00:00Z` (window is 30 days). *Actual:* 201, meeting created.
- *Cause:* `isSlotAvailable` never checks `bookingWindowDays` — `src/lib/availability.ts:116-141`.

**F-08 — Invalid business timezone is accepted and silently disables booking**
- *Repro:* Settings → timezone `Mars/Olympus` → save (accepted) → availability returns `[]`, every booking 409.
- *Location:* `src/app/admin/(protected)/settings/actions.ts:28` (`z.string().min(1)` only).

**F-09 — Whitespace-only required fields are accepted**
- *Repro:* Services → Add → title and description `"   "` → saved; a blank row appears.
- *Cause:* `z.string().min(1)` without `.trim()` (`services/actions.ts:9-10`). Same pattern in other modules' schemas — *Unverified* in browser beyond Services.

**F-10 — No length limits on public input**
- *Repro:* `POST /api/leads` with a 2 MB `message` → 201, stored and emailed.
- *Location:* `src/app/api/leads/route.ts:6-14`, `src/app/api/meetings/book/route.ts:10-15`.

**F-11 — Login timing reveals which emails are admins**
- *Repro:* 5 attempts each: existing email avg **56 ms**, unknown email avg **3 ms**.
- *Cause:* bcrypt only runs when the user exists — `src/auth.ts:24-28`.

**F-12 — No security headers**
- *Repro:* `curl -I /` → no `Content-Security-Policy`, `X-Frame-Options`/`frame-ancestors`, `Strict-Transport-Security`, `X-Content-Type-Options`, `Referrer-Policy`; `X-Powered-By: Next.js` present.
- *Location:* `next.config.ts` (empty); `deploy/nginx.conf` sets none either.

**F-13 — Upload trusts the browser-declared MIME type**
- *Repro:* upload an HTML file declared as `image/png` → accepted, served as `image/png` without `nosniff`.
- *Also:* the whole multipart body is read (`request.formData()`) before the 5 MB check, so oversized bodies are buffered in memory first.
- *Location:* `src/app/api/upload/route.ts:22-35`, `src/app/uploads/[filename]/route.ts:33-35`.
- *Passed:* SVG rejected, > 5 MB rejected, unauthenticated 401, `..%2F` / `%5c` traversal → 400.

## 5. Phase 3 — design proposal (awaiting approval)

### 5.1 Role model — recommendation: one `User` model, mapped onto the existing table

Rename the **Prisma model** (not the table) and widen the enum. Existing rows, IDs and passwords stay exactly as they are.

```prisma
enum Role {
  SUPER_ADMIN
  ADMIN
  USER
  @@map("AdminRole")          // same Postgres enum type
}

enum AccountStatus { ACTIVE SUSPENDED }

model User {
  id                 String        @id @default(cuid())
  email              String        @unique
  passwordHash       String
  name               String
  role               Role          @default(USER)
  status             AccountStatus @default(ACTIVE)
  sessionVersion     Int           @default(0)   // bump = force logout everywhere
  failedLoginCount   Int           @default(0)
  lockedUntil        DateTime?
  lastLoginAt        DateTime?
  totpSecret         String?                      // encrypted at rest, SUPER_ADMIN only
  totpEnabledAt      DateTime?
  createdAt          DateTime      @default(now())
  updatedAt          DateTime      @updatedAt
  auditEntries       AuditLog[]    @relation("actor")
  @@map("AdminUser")          // same table
}

model AuditLog {
  id          String   @id @default(cuid())
  actorId     String?
  actor       User?    @relation("actor", fields: [actorId], references: [id], onDelete: SetNull)
  actorEmail  String                     // snapshot; survives actor deletion
  actorRole   Role
  action      String                     // e.g. "service.update", "user.suspend"
  entityType  String
  entityId    String?
  before      Json?
  after       Json?
  ip          String?
  userAgent   String?
  createdAt   DateTime @default(now())
  @@index([createdAt])
  @@index([actorId, createdAt])
  @@index([entityType, entityId])
}

model RateLimit {                        // replaces nothing; new
  key        String   @id                // e.g. "login:ip:1.2.3.4"
  count      Int
  windowEnd  DateTime
}
```

**Migration (additive only, no reset):**
1. `ALTER TYPE "AdminRole" ADD VALUE 'SUPER_ADMIN'; ADD VALUE 'USER';`
2. `CREATE TYPE "AccountStatus"…`; `ALTER TABLE "AdminUser" ADD COLUMN …` with defaults — every existing row becomes `ACTIVE`, `sessionVersion 0`.
3. Change the column default from `ADMIN` to `USER` (existing rows keep `ADMIN`).
4. `CREATE TABLE "AuditLog"`, `"RateLimit"`.
5. Separate migration for F-01: drop `Meeting_scheduledAt_key`, add `CREATE UNIQUE INDEX … ON "Meeting"("scheduledAt") WHERE status = 'CONFIRMED'`.

Why not a second `User` table: two credential stores means two login paths, two lockout policies and a cross-table "who is this?" for every audit row. One table with a role is simpler and the `@@map` keeps the migration non-destructive.

### 5.2 `middleware.ts` + `requireRole(minRole)`

- **`src/auth.config.ts`** (edge-safe, no Prisma) holds callbacks that put `id`, `role`, `sessionVersion` into the JWT; `src/auth.ts` adds the Credentials provider. Standard Auth.js v5 split.
- **`middleware.ts`** (coarse, fast): `/admin/**` without an ADMIN+ token → redirect to `/admin/login`; `/account/**` without a session → `/login`; the hidden console path (5.3) → rewrite or **404**. Also sets the security headers from F-12 (or they go in `next.config.ts`).
- **`src/lib/auth/require-role.ts`** (authoritative, Node): `requireRole(min, { onFail: "throw" | "notFound" | "redirect" })` loads the user from the DB on every call, checks `status === ACTIVE`, `sessionVersion` match, and role rank `SUPER_ADMIN(3) > ADMIN(2) > USER(1)`. This is what fixes F-03. It also stores `{ actor, ip, userAgent }` in an `AsyncLocalStorage` for the audit helper.
- Replace all 43 `assertAdmin()` calls with `requireRole("ADMIN")`; pages/layouts use `onFail: "redirect"`; `/api/upload` uses it too. Delete `admin-guard.ts`.

### 5.3 Hidden super-admin console

- **Path:** real route lives at `src/app/sa-console/**`. Middleware maps `/${SUPER_ADMIN_PATH}` (env var, ≥ 32 random chars) → internal rewrite to `/sa-console`, and returns **404** for any direct request to `/sa-console` or for any non-SUPER_ADMIN session on the secret path. Pages also call `requireRole("SUPER_ADMIN", { onFail: "notFound" })`, so a middleware mistake still yields 404, not 403.
- `robots: { index: false }` metadata + `X-Robots-Tag: noindex`; not in sitemap; `robots.txt` disallows `/admin` but **does not mention** the console path (listing it would reveal it).
- **Features:** list/search users and admins; create admin or user; suspend / reactivate; delete (soft-confirm by typing the email); reset password (sets a one-time password, forces change on next login); change role — server refuses to demote or suspend the last active SUPER_ADMIN and refuses self-demotion; **force logout** = `sessionVersion++`; read-only view of any account's data; global read-only views of leads, meetings and content; **audit log viewer** filterable by actor, action, entity, date range, with before/after diff.
- **SUPER_ADMIN creation:** `pnpm seed:super-admin --email … --password …` (CLI only); no UI or API path can grant SUPER_ADMIN except an existing SUPER_ADMIN's role change, which is itself audited.
- **Audit coverage:** a helper `audited({ action, entityType, entityId }, async (before) => after)` wraps every admin and super-admin mutation (read before → run → write `AuditLog` with diff, in one transaction). Logins, failed logins, lockouts and force-logouts are logged too. IP from `X-Forwarded-For` first hop (nginx sets it, `deploy/nginx.conf:38`); only trusted behind the proxy.
- **Optional TOTP 2FA for SUPER_ADMIN:** RFC 6238 implemented with `node:crypto` (no dependency). Without a QR library the setup screen shows the `otpauth://` URI and the base32 secret for manual entry; a QR code would need a new dependency.

Deploy configuration problems:

There is no `packageManager` or `engines` pin. This is Unverified, but pnpm 11 is very likely to fail on Node 18. Fix: pin `"packageManager": "pnpm@11.x"` and `"engines": {"node": ">=22"}`, and update DEPLOY.md.
- **D-11 (Low): no startup check for placeholder secrets.** The app starts with `AUTH_SECRET="changeme"` and `SITE_URL` unset (it falls back to `http://localhost:3000` in `metadataBase`, the sitemap and robots). Fix: fail fast in production if either is a placeholder.

- **D-14 (Info): `pg-backup.sh` keeps backups on the same disk as the database, with no off-site copy.** Restore has never been tested on this setup. This is Unverified.
